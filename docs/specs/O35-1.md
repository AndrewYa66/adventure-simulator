# O35-1 隊伍與多對多戰鬥 規格書

> 狀態：review 第 1 輪修正完成、待第 2 輪 review（2026-11-26；交接單 `docs/specs/O35-1-handoff.md`）。分支 `module/O35-1`（從 main 開）。

> O35 分三階段：**O35-1 隊伍與多對多戰鬥**（本規格書）、O35-2 好感度、對已知事件的反應、個人任務、O35-3 紮營與營地對話、對話檢定協助。

## 目標（一句話）

玩家可以由規則招募同伴組成隊伍一起移動，戰鬥改為依 SPD 排序的多對多戰鬥，同伴與敵人都由規則行動，AI 只負責敘事與插話。

## 範圍內 / 範圍外 / 延後

### 範圍內
1. 單位資料的 `companion` 設定（可招募、入隊條件）；範例同伴：獵人伊凡（NPC-006）。
2. 入隊：選項列「🤝 邀請 X 同行」（條件成立時）與劇情片段／事件效果；離隊：選項列「👋 請 X 離隊」、同伴或其勢力轉敵對時自動離隊。隊伍上限 3 位同伴。
3. 同伴跟隨：所在地＝玩家所在地（含多段移動與途中遭遇），不再算原居所的在場居民；算在場目擊者；在隊伍中暫停重要角色每日決策。
4. 同伴的 HP、MP、狀態記在單位實例；玩家恢復資源時隊伍一起恢復；治療技能與道具可對我方任一人使用（戰鬥內外）。
5. 族群樣板的成群遭遇（`groupSize`），成群敵人在戰鬥中各有編號。
6. 多對多戰鬥：SPD 行動順序、自動結算到玩家回合、同伴規則行為、仇恨權重與嘲諷狀態、昏迷對所有單位一致、切換鎖定目標、全隊逃跑、勝利結算、同伴倒地與起身。
7. O45 開場方式套用到多對多（一般、伏擊、陷阱、敵方偷襲）；成群對抗檢定用敵方最高值。
8. 修正舊問題：擊倒時只結算目標吻合的任務。
9. AI 上下文：隊伍成員、戰鬥中的行動順序與雙方 HP；主持規則允許同伴插話、禁止 AI 宣稱入隊離隊或替同伴改變狀態。
10. HUD：隊伍成員與戰鬥區（雙方 HP、行動順序、目前行動者）。
11. 存檔版本 17（O50-2 先合併則 18）。
12. 同伴敘事與狀態不符的輕量處理（D34，2026-11-26 新增，review 第一輪修正時實作）。

### 範圍外
- 好感度、對事件的贊同或反對、個人任務、好感度驅動的離隊或反目（O35-2）。
- 紮營與營地對話、同伴參與對話檢定與交涉（O35-3）。
- 玩家指揮同伴、給同伴裝備或交換物品。
- 嘲諷技能本身（O46 技能習得重做時加入；O35-1 只做嘲諷「狀態」與仇恨權重）。
- 昏迷、嘲諷以外的狀態效果（O17）。
- AI 回應格式變更（打字邀請不會直接入隊）。
- 戰鬥中途有敵人加入、敵人逃跑。
- 舊戰鬥快照轉換（照存檔政策捨棄舊存檔）。

### 延後（寫進 PROJECT_GOALS）
- 戰鬥中重新整理等於免費脫戰（O45 延後項目，O35-1 維持延後；重新整理時整隊回到戰前，行為一致）。
- 王國指派同伴「每 5 天寄報告」等同伴專屬規則（O35-2）。
- 新劇本三位同伴的資料（待寫手）。

## 資料與介面變更

- **`units.json`**：單位可加 `companion`（至少：`recruitable`、入隊條件 `joinConditions`，可用旗標、勢力聲望與「不敵對」；離隊回 `homeMapId`）。族群樣板可加 `groupSize: { min, max }`（未設定為 1）。範例：伊凡加 `companion`；斥候 1～2、打手 1、狼 1～3。`validate:data` 檢查欄位與範圍（min ≥ 1、max ≥ min）。
- **規則數值**（可調，放在 `action_methods.json` 的 `combatRules` 底下獨立的隊伍區塊，或新資料檔，製作者自行決定，不改既有手段）：同伴上限 3、仇恨權重（玩家 2、同伴 1）、同伴治療門檻 40%、倒地起身 HP 1。
- **劇情片段／事件效果**：新增「同伴入隊」「同伴離隊」效果（以單位 ID 指定，驗證為可招募的存活單位）。
- **型別與存檔**（`SAVE_SCHEMA_VERSION` 16 → 17）：
  - 角色層：隊伍成員清單。
  - 世界層單位實例：補 `currentMp`、狀態效果（昏迷、嘲諷）、倒地。
  - `CombatState`：參與者為多個我方與多個敵方，每個參與者有獨立編號（成群的同種敵人可區分）、行動順序、目前行動者；`opening` 沿用 O45。
- **AI 上下文**：隊伍成員、戰鬥中的行動順序與雙方 HP；主持規則補 D25、D26。**回應格式不變**（第 6 版）。
- **選項列**：邀請同行、請離隊、戰鬥中切換鎖定目標、治療技能與道具選對象。
- **HUD**：隊伍成員（名字、HP、MP、倒地）、戰鬥區（雙方 HP、行動順序、目前行動者）。視覺樣式由 Andrew 測試時確認。
- **`docs/API.md`**：同步更新存檔、資料與戰鬥說明。

## 驗收條件

先逐項通過 `docs/製作流程.md` 的「通用 review 檢查清單」，再檢查以下各條。

1. 伊凡條件成立時選項列有「邀請同行」，不成立時（敵對或聲望低於中立）沒有；入隊後跟著玩家多段移動到古道，村裡的在場名單與 AI 上下文沒有他、玩家所在地有他；請離隊後回到村裡，可再邀請；隊伍滿 3 位時不能再邀請。— Playwright（AI 以模擬回應攔截）
2. 劇情片段或事件的入隊、離隊效果生效，非法單位被拒絕。— 暫時 Node 腳本
3. 同伴在隊伍中時不做每日決策，離隊後恢復。— 暫時 Node 腳本
4. 行動順序依 SPD 由高到低，同速時我方、玩家優先；固定亂數下整場戰鬥結果可重現。— 暫時 Node 腳本（固定亂數）
5. 一次玩家行動後，同伴與敵人自動結算到下次輪到玩家，系統訊息每個行動者一行；玩家昏迷時自動跳過。— 暫時 Node 腳本＋ Playwright 截圖
6. 同伴規則行為：有人 HP 低於 40% 且有治療技能與 MP 時治療最低者，否則攻擊玩家鎖定目標，目標倒下改打 HP 最低者。— 暫時 Node 腳本
7. 仇恨權重：大量次數統計下玩家被選中的比例約為權重比例；嘲諷狀態期間敵人只打施放者；倒地者不會被選中。— 暫時 Node 腳本
8. 同伴倒地：勝利或逃跑成功後以 1 HP 起身；玩家 HP 歸零照舊死亡讀檔。— 暫時 Node 腳本＋ Playwright
9. 全隊逃跑：DC 用敵方最高 SPD；失敗敵人照常行動。— 暫時 Node 腳本（固定亂數）
10. 兩隻同種敵人分別受傷、分別擊倒、各給一次經驗與掉落；全部倒下才勝利；玩家與每位存活同伴各拿完整經驗。— 暫時 Node 腳本
