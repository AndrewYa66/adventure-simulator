# 專案任務目標

## 專案願景

打造一款可在瀏覽器遊玩的繁體中文文字冒險遊戲，由玩家選擇的生成式 AI 擔任遊戲主持人，結合可追蹤的玩家存檔與靜態遊戲資料，讓玩家能持續探索、接任務、戰鬥並成長。

## 目前範圍

- React + TypeScript 前端，使用 Vite 建置並部署為靜態網站。
- 玩家可選擇 Google Gemini 或 OpenAI 模型；目前由瀏覽器直接呼叫所選服務。
- 遊戲資料以 JSON 隨前端部署；玩家狀態以 `localStorage` 保存。
- 遊戲回合由玩家行動、GM 敘事、建議行動和可選狀態變更組成。

## 任務目標與驗收條件

### P0 — 建立可靠的冒險回合

- 玩家能設定 API Key、送出自由輸入行動並收到 GM 回應。
- AI 回應能按 `AIResponsePayload` 契約解析；解析失敗時顯示可理解的備援訊息，不讓介面崩潰。
- HP、MP、經驗、金幣、道具、地圖與劇情旗標只依有效狀態變更更新。
- 結果不確定且失敗有影響的行動使用前端 d20 檢定；成功/失敗分支由檢定結果選擇，AI 負責敘事。
- 429、503 或網路暫時錯誤時會有限次重試；最後失敗會顯示錯誤且解除載入狀態。

### P0 — 保護並維持玩家存檔

- 新玩家能建立有效的預設角色狀態。
- 玩家狀態修改後可保存，重新載入頁面仍能恢復。
- 無效或舊版存檔不會令遊戲初始化失敗；需提供安全回復預設存檔的方式。
- 玩家可清除或重設存檔，且操作結果清楚可見。

### P1 — 完成核心遊戲資料循環

- 靜態 JSON 中的物品、地圖、怪物、等級和任務均具唯一 ID，並能互相正確參照。
- 玩家可取得、移除及檢視背包道具；數量不為負值，無效 item ID 不會污染存檔。
- 玩家可接取/完成任務並持續保存任務狀態。
- 地圖移動限制在有效連通地圖，顯示目前位置及可探索地點。

### P1 — 讓進度可玩且可理解

- 經驗累積與升級門檻依 `player_growth.json` 設定處理，升級會套用對應角色成長。
- 戰鬥結果依明確遊戲規則結算，AI 敘事不能任意繞過核心數值限制。
- 對話紀錄能保留足以延續遊戲的劇情摘要，避免只依賴短期訊息或無限制累加上下文。
- 玩家能辨識建議行動、載入中、API 錯誤及存檔狀態。

### P2 — 發佈品質與維護性

- API/資料格式變更同步更新文件與型別。
- 建置與 lint 可成功，GitHub Pages 部署後主要遊戲流程可使用。
- 文件說明設定方式、API Key 儲存位置、存檔位置和已知限制。
- 評估是否引入後端代理以避免 API Key 暴露於使用者瀏覽器；若維持純前端，需清楚告知玩家此安全界線。

## 預計優化目標

以下項目已列入規劃，尚未實作；後續可逐項拆成獨立功能模組。

### O1 — 可收合的遊戲選單

- 讓側邊選單可由玩家展開或隱藏，收合後仍保留清楚的重新開啟入口。
- 驗收：選單開合不遮住主要劇情和行動輸入；窄螢幕也能使用。

### O2 — 由遊戲資料約束任務與獎勵

- 任務目標、可接受進度、獎勵種類與數量由遊戲資料或規則設定提供有效範圍及上限。
- AI 可協助敘述任務或在已定義選項內提出內容，但不能自行提高獎勵、建立超出限制的目標或直接判定未達成條件的任務完成。
- 驗收：任務及獎勵經前端規則驗證；超出範圍或不符合條件的 AI 回應不會改動存檔。

### O3 — 地區狀態與介面同步

- 將 `currentMapId` 作為唯一目前地區來源；玩家移動或 AI 回傳地區變更後，介面位置、提供給 AI 的狀態及存檔都同步更新。
- 驗收：每次地區切換後，HUD 顯示位置、附近地點和 AI 行動脈絡一致；非法地區或不連通移動不會造成畫面與存檔不一致。

### O4 — 玩家與敵方行動都進行擲骰

- 戰鬥按回合拆解雙方行動：玩家發動攻擊時顯示攻擊檢定；敵方反擊時依玩家能力觸發閃避或防禦檢定。
- 每次攻防都分別呈現骰數、骰面、能力修正、目標值、成功/失敗和對應結果，不讓後續連續行動退化成純 AI 敘事。
- 驗收：每個造成或避免戰鬥效果的行動都有可追蹤的檢定與結算；AI 只負責敘事，不能省略擲骰或單方面決定攻防結果。

### O5 — 中斷後恢復遊戲進度

- 每次玩家行動完成並收到 AI 回應後，保存可恢復的遊戲快照，包含玩家狀態、目前地區、進行中的戰鬥及回合階段、任務進度與近期對話紀錄。
- 重新進入遊戲時，優先載入最近一次完整快照，恢復到一致的地區和戰鬥情境；若快照損壞或版本過舊，安全退回有效存檔並提示玩家。
- 驗收：重新載入頁面或中斷後，玩家看到的地區、戰鬥狀態、任務及對話上下文與最後完成回合一致；未完成或失敗的 AI 請求不會留下半套狀態。

### O6 — 完成任務時交付需求道具

- 任務資料需明確標示完成時必須交付的道具與數量；任務完成結算時，從玩家背包扣除對應道具，再發放任務獎勵。
- 若玩家道具不足或任務條件未滿足，任務不得完成、不得扣除道具，也不得發放獎勵；同一任務不得重複交付或重複領獎。
- 驗收：每筆 `collectItems` 需求都有一致的檢查與扣除結果，並在介面清楚顯示已交付及尚缺項目。

## 建議里程碑

1. **Alpha 穩定化：** 完成回合錯誤處理、狀態驗證、存檔復原與重設。
2. **可玩垂直切片：** 完成一條任務、一張可探索地圖、至少一場有規則的戰鬥與升級循環。
3. **內容擴充：** 擴充地圖、NPC、任務、道具和怪物，補足資料參照檢查。
4. **公開版本：** 完成部署驗收、使用說明、存檔/API Key 提示與核心流程回歸驗收。

## 不在目前範圍

- 多人連線、帳號系統、雲端同步與伺服器端存檔。
- 專案自行託管或轉售第三方模型服務 API Key。
- 未經玩家操作而自動呼叫付費或有配額限制的外部服務。
