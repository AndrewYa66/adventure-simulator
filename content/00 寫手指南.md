# 寫手指南

歡迎一起寫這個世界！這份指南說明要寫什麼、怎麼寫，以及要注意哪些規則。第一次參與時請從頭讀一遍，之後當成查詢手冊使用即可。

## 1. 你寫的東西會怎麼被使用

這是一款由 AI 擔任遊戲主持人的文字冒險遊戲，風格接近《柏德之門》。分工如下：

- **你負責骨架和靈魂**：世界設定、角色個性、關鍵劇情要傳達什麼、絕對不能發生什麼。
- **AI 負責血肉**：根據你的設定，即時寫出對話、場景描寫，以及玩家選擇後的反應。

所以你**不需要寫完整的劇本或每一句台詞**，而是要讓 AI 清楚知道「這個角色是怎樣的人」「這段劇情要達成什麼」。寫得越具體，AI 演得越像。

每個檔案分成兩部分：

1. **屬性**（檔案最上方的欄位）：給遊戲程式讀，決定劇情什麼時候發生、誰參與、改變什麼。格式要照規則填。
2. **內文**（下方的段落）：給 AI 讀，可以自由撰寫。段落標題不要改，程式會依標題挑出需要的段落給 AI。

## 2. 開始前的設定（只需做一次）

1. 安裝 [Obsidian](https://obsidian.md/)（免費）。
2. 確認你的電腦已同步共用雲端資料夾（Google Drive 或 OneDrive）。
3. 開啟 Obsidian →「開啟資料夾作為儲存庫」→ 選擇共用資料夾裡的 `content` 資料夾。
4. 開啟範本功能：設定 → 核心外掛 → 開啟「範本」。
5. 設定範本位置：設定 → 範本 → 範本資料夾位置，選 `_templates`。
6. （建議）設定快捷鍵：設定 → 快捷鍵 → 搜尋「範本：插入範本」，設成你習慣的按鍵。

## 3. 資料夾說明

| 資料夾或檔案 | 內容 |
| --- | --- |
| `00 寫手指南` | 就是這份文件 |
| `01 ID 登記表` | 所有內容的編號，建立新檔前先登記 |
| `02 旗標清單` | 所有旗標（劇情狀況）的清單 |
| `03 職階清單` | 角色卡可用的職階 |
| `characters/` | 角色卡：NPC、具名魔物、同伴 |
| `story/act1/`、`story/act2/`… | 每一幕的「幕」檔案與「劇情片段」 |
| `events/` | 世界事件 |
| `lore/` | 世界設定：敘事風格、世界局勢、勢力（FAC）、種族（RACE）等。**開始寫之前，請先讀 `LORE-001 世界局勢`** |
| `_templates/` | 範本，**不要直接修改** |
| `_examples/` | 填寫範例，可以參考，不會進入遊戲 |

## 4. 建立新檔案的步驟

1. 到「01 ID 登記表」找到對應類別，用下一個號碼登記，狀態寫「保留」。
2. 在對應資料夾建立新檔案，檔名格式為 **「ID 名稱」**，例如 `NPC-007 席拉`、`STORY-1-02 夜襲`。
3. 用快捷鍵或命令面板插入對應範本。
4. 把屬性裡的 `id` 改成你登記的 ID，並填寫其他欄位。
5. 寫內文。灰色的 `%% … %%` 是填寫說明，寫完後可以刪掉，留著也沒關係，不會給 AI 看到。
6. 寫好後把「狀態」改成「審閱中」，並通知維護者。

## 5. 屬性的共通規則

- **不要改屬性名稱**（冒號左邊的字），只改右邊的值。
- 標示「清單」的欄位可以填多個值，在 Obsidian 屬性欄位中按 Enter 逐一新增。
- **可選值**有規定的欄位，請照下方表格一字不差填寫。
- **引用其他內容**時有兩種寫法，擇一即可：
  - 直接寫 ID：`MAP-001`
  - 用連結：輸入 `[[` 後選擇檔案，例如 `[[NPC-001 埃爾德]]`。連結的好處是可以點擊跳轉，檔案改名時也會自動更新。
  - 地圖和物品沒有檔案，請直接寫 ID，並查「01 ID 登記表」。
- 不需要的欄位留空即可，不要刪除。
- 「作者」填你的名字；「更新日期」每次大幅修改後更新。

### 共通欄位

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| 狀態 | 草稿／審閱中／定稿 | 只有「定稿」會進入遊戲 |
| 作者 | 你的名字 | 負責人，其他人要修改請先告知 |
| 更新日期 | YYYY-MM-DD | 範本會自動填入 |

## 6. 角色卡（`characters/`）

用於所有有名字的角色：NPC、具名魔物（例如首領）、同伴。一般雜兵不需要角色卡。

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| id | NPC-xxx 或 MON-xxx | 人物用 NPC，具名魔物用 MON |
| 名稱 | 文字 | 角色名字 |
| 稱號 | 文字 | 職稱或外號，例如「村長」「裂牙」 |
| 單位類型 | NPC／魔物 | |
| 種族 | RACE-xxx 或連結 | 見 `lore/` 中的種族條目，例如 `[[RACE-001 人類]]` |
| 職階 | 職階中文名稱 | 從「03 職階清單」選擇，例如長老、工匠、戰士；野獸留空 |
| 勢力 | FAC-xxx 或連結 | 見 `lore/` 中的勢力條目，例如 `[[FAC-001 橡木村]]`；野獸留空 |
| 陣營傾向 | 守序善良／中立善良／混亂善良／守序中立／絕對中立／混亂中立／守序邪惡／中立邪惡／混亂邪惡 | 角色的價值觀，**不等於**對玩家友不友善 |
| 所在地 | MAP-xxx | 一開始在哪裡 |
| 預設關係 | 友善／中立／敵對 | 遊戲開始時對玩家的態度，之後會隨劇情改變 |
| 重要角色 | 勾選／不勾選 | 勾選後，這個角色會由 AI 依他的目標和個性自己做決定 |
| 同伴 | 勾選／不勾選 | 可以加入玩家隊伍的角色，需填寫「同伴設定」段落 |
| 目標 | 清單 | 角色想達成的事，每項一句短句 |
| 個性 | 清單 | 2～4 個形容詞 |
| 預設行為 | 守護／經商／巡邏／流浪／掠奪／隱居 | AI 沒有替他做決定時，他平常會怎麼行動 |
| 繼承者 | 清單（角色 ID 或連結） | 這個角色死亡時，誰會接手他的職責和目標 |

**注意：** HP、攻擊力等數值不在角色卡填寫，由維護者另外設定。如果有想法，可以寫在「審閱意見」裡，例如「希望他很弱但很會逃」。

## 7. 幕（`story/actN/`）

主線分成好幾「幕」。一幕代表一個大階段，不管玩家走哪條路，最後都會收斂到這一幕的目標。

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| id | ACT-編號 | 例如 ACT-1 |
| 標題 | 文字 | |
| 順序 | 數字 | 第幾幕 |
| 預設片段 | STORY-ID | 這一幕的保底劇情片段，通常是 STORY-幕-00 |
| 卡死保底事件 | EVT-xxx | 這一幕走不下去時發生的事件，見第 8 節「卡死保底」；最後一幕可留空 |

## 8. 劇情片段（`story/actN/`）

劇情片段是主線中的一小段劇情。遊戲會根據世界目前的狀況，挑出「現在可以發生」的片段，再由 AI 選擇最自然的一個演出。

### 什麼時候發生

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| id | STORY-幕-編號 | 例如 STORY-1-02 |
| 所屬幕 | ACT-編號 | |
| 優先度 | 0～100 | 同時有多個片段可以發生時，數字大的優先 |
| 預設片段 | 勾選／不勾選 | 每一幕必須有一個預設片段，見下方說明 |
| 需要旗標 | 清單 | 這些狀況**全部成立**才會發生 |
| 排除旗標 | 清單 | 這些狀況**任一成立**就不會發生 |
| 需要存活 | 清單（角色） | 這些角色都活著才會發生 |
| 需要死亡 | 清單（角色） | 這些角色都死了才會發生 |
| 發生地點 | 清單（MAP-xxx） | 留空代表任何地點 |

### 誰給予

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| 首選給予者 | 角色 | 最理想由誰帶出這段劇情 |
| 給予者職階 | 清單 | 首選給予者不在時，具有這些職階的角色可以接手 |
| 給予者勢力 | FAC-xxx 或連結 | 接手的人必須屬於這個勢力 |
| 給予者最低等級 | 數字，可留空 | 接手的人至少要幾級 |
| 接手範圍 | 本地／全世界 | 本地：只找「發生地點」（沒填時為首選給予者住的地方）的人接手；全世界：任何地方的人都可以 |
| 保底管道 | 告示板／書信／遺物／無 | 連接手的人都沒有時，用什麼方式讓玩家得知。主線片段（會推進下一幕，或設定其他片段需要的旗標）**不可填「無」**；「告示板」只在有告示板的地點能用（發生地點至少要有一處有告示板），「書信」哪裡都能用；「遺物」目前遊戲還不支援 |

接手的順序：首選給予者還活著、沒有敵對時，一定由他帶出這段劇情（玩家要去找他）；他死了或和玩家敵對時，才由符合職階、勢力、等級的人接手；都沒有人時才用保底管道。

### 怎樣算完成

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| 目標類型 | 威脅消除／抵達地點／說服角色／保護角色／得知真相／其他 | 選「其他」時，請在內文詳細說明 |
| 目標對象 | 見下方 | |
| 或旗標成立 | 旗標名稱，可留空 | 只用於威脅消除、抵達地點：這個旗標成立時同樣算完成，用來支援另一種解法 |
| 目標說明 | 一句話 | 給玩家看的目標，例如「前往綠林古道查看情況」 |

目標對象的寫法：

- 威脅消除：特定角色，`MON-003` 或 `[[MON-003 格羅姆・裂牙]]`，可以列多個（全部死亡才算完成）
- 抵達地點：`MAP-003`
- 說服角色、保護角色、得知真相、其他：填一個**旗標名稱**，並另外寫一個「AI提議」事件來設定這個旗標（例如玩家說服成功時，AI 提議事件「酋長同意撤離」，事件設定旗標「酋長被說服」）
- 目前還不支援：某地區的某類敵人（例如 `哥布林@MAP-003`，因為一般魔物會重生）、物品送達。需要時請改用旗標。

**重要：目標寫的是「結果」，不是「手段」。** 例如「哥布林酋長的威脅消除」，玩家可以殺了他、說服他離開，或者別人先把他解決了，都算完成。寫法是：目標類型「威脅消除」、目標對象 `MON-003`（他死了就算，不管誰下的手），再把「或旗標成立」填「酋長被說服」，另外寫一個 AI提議 事件（例如「酋長同意撤離」）在玩家說服成功時設定這個旗標。

完成後改變的東西（完成旗標、結局特徵、完成描述）不分玩家走哪條路，所以要寫「結果」本身，例如結局特徵寫 `古道威脅:已解除`，不要寫 `酋長:已死`；需要區分走哪條路時，看事件設定的旗標（例如「酋長被說服」）或角色是否死亡即可。

### 完成後改變什麼

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| 完成事件 | 清單（EVT-xxx） | 完成時觸發的世界事件 |
| 完成旗標 | 清單 | 完成時成立的狀況 |
| 推進下一幕 | 勾選／不勾選 | 完成後是否進入下一幕 |
| 結局特徵 | 清單，格式「項目:值」 | 影響最終結局，例如 `村莊:倖存`、`酋長:被說服` |
| 完成描述 | 一句話 | 完成時寫進世界紀錄的公開結果，NPC 之後會以此談論這件事，例如「哥布林酋長倒下，古道的威脅解除」 |
| 完成傳播範圍 | 目擊者／本地區／全世界 | 誰會知道這個結果，預設本地區 |

### 預設片段（保底）

每一幕都必須有一個「預設片段」，確保主線**無論如何都能繼續**，即使所有重要角色都死了，或玩家和所有人為敵。預設片段的規則：

- 勾選「預設片段」，優先度設為 0。
- 「需要旗標」「需要存活」盡量留空。
- 首選給予者、給予者職階、給予者勢力都留空，保底管道選告示板或書信。
- 預設片段只在這一幕「沒有其他路可走」時才會出現（其他片段都還沒條件發生、給予者都不在了，或目標已經不可能達成），平常玩家不會看到它。
- 最後一幕以外，預設片段必須勾選「推進下一幕」。

### 卡死保底

有時候連預設片段都走不下去，例如目標角色住的地方再也進不去。遊戲會自動檢查：這一幕還有沒有任何片段「有機會」完成。如果沒有，而且持續一個遊戲日：

1. 先發生這一幕的「卡死保底事件」（觸發方式選「卡死保底」，發生地點留空）。事件描述世界發生了什麼讓故事繼續，例如「酋長在內鬨中失勢，帶著殘部遁入深山」。事件也可以設定旗標，開出一個救援用的劇情片段。
2. 事件發生後仍然走不下去，遊戲會**直接完成預設片段**，進入下一幕。

所以寫預設片段的「完成描述」與「結局特徵」時，要讓它在「沒有人真的完成目標」的情況下也讀得通。卡死保底是最後手段，正常遊玩時不應該出現。

另外，片段用到的旗標（需要旗標、目標旗標、或旗標成立）都必須有某個事件或片段會設定它，否則檢查會報錯。

## 9. 事件（`events/`）

事件是「已經發生的事實」，會**永久**改變這個存檔的世界，例如「酋長死亡」「村莊被燒毀」。事件沒有目標，也不會失敗。

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| id | EVT-xxx | |
| 觸發方式 | 自動／劇情片段完成／卡死保底／角色決策／AI提議 | 「自動」代表條件成立就發生；「卡死保底」見第 8 節 |
| 需要旗標、排除旗標、需要存活、需要死亡、發生地點 | 同劇情片段 | 發生條件 |
| 設定旗標 | 清單 | 事件發生後成立的狀況 |
| 移除旗標 | 清單 | 事件發生後不再成立的狀況 |
| 影響單位 | 清單（角色） | 會被影響的角色 |
| 影響地區 | 清單（MAP-xxx） | 會被影響的地區 |
| 傳播範圍 | 目擊者／同勢力／本地區／全世界 | 誰會知道這件事。角色只會根據自己知道的事做決定 |

具體的數值影響，例如「攻擊力下降 10%」，請用文字寫在「世界影響」段落，由維護者轉成遊戲數值。

## 10. 設定條目（`lore/`）

世界觀資料：歷史、地理、勢力、種族、文化、宗教等。

| 欄位 | 可填值 | 說明 |
| --- | --- | --- |
| id | LORE-xxx；勢力用 FAC-xxx；種族用 RACE-xxx | |
| 分類 | 敘事風格／歷史／地理／勢力／種族／文化／宗教／其他 | |
| 相關 | 清單 | 相關的角色、地圖、其他條目 |
| AI使用 | 總是／相關時／僅作者 | 「總是」每回合都給 AI，請**只用在很短的核心設定**；「相關時」在提到相關內容時才給；「僅作者」AI 不會看到 |

`LORE-000 敘事風格` 是全遊戲的文風基準，每一回合都會給 AI 看，請保持精簡。

## 11. 寫作原則

1. **寫目的，不寫劇本。** 與其寫十句台詞，不如寫清楚「這段要讓玩家懷疑村長」。
2. **寫具體細節。** 「很兇」不如「說話時會用刀尖敲桌子」。
3. **祕密要分開寫。** 放在「祕密」或「未揭露的真相」段落，AI 才知道不能主動說出來。
4. **禁止事項要明確。** 劇情片段的「禁止事項」是防止 AI 搶戲或劇透的最後防線。
5. **假設任何角色都可能死。** 世界會永久改變，所以重要劇情要想好「給予者不在時」怎麼辦。
6. **不要在內文裡寫遊戲數值或規則。** 例如「給玩家 500 金幣」「直接完成任務」，AI 不會照做，遊戲規則也會擋下。獎勵和數值請在「審閱意見」裡提出。

## 12. 協作規則

- **一次一個人編輯一個檔案。** 要修改別人的檔案，先告知作者，或把建議寫在「審閱意見」。
- 如果雲端資料夾出現「衝突副本」（檔名後面多了日期或電腦名稱），不要刪除，通知維護者合併。
- **不要修改** `_templates/` 裡的範本。有建議請告訴維護者。
- 新的旗標、地圖、ID 都要先登記再使用。

## 13. 審閱流程

1. **草稿**：自由撰寫中。
2. **審閱中**：作者覺得完成了，等維護者或其他寫手檢查。意見寫在檔案最下方的「審閱意見」，每條前面加上自己的名字。
3. **定稿**：確認沒問題，會在下次同步時進入遊戲。

定稿後如果要修改，改回「審閱中」，並在審閱意見說明改了什麼。

## 15. 常見問題

**Q：我不確定某個欄位要填什麼？**
留空，並在「審閱意見」寫下你的想法，維護者會協助。

**Q：我想新增一張地圖或一個新物品？**
寫在「審閱意見」或 ID 登記表的備註，由維護者建立。

**Q：可以寫只在某個條件下才會出現的對話嗎？**
可以。寫在劇情片段的「可能的玩家選擇與後果」，或角色卡的「動機與目標」，例如「如果玩家曾經救過他的女兒，他會……」。

**Q：我寫的關鍵台詞，AI 會一字不差說出來嗎？**
不一定。AI 會保留意思和語氣，但可能依情境調整措辭。如果某句話一定要一字不差，請在旁邊註明「必須原文」，並謹慎使用。
